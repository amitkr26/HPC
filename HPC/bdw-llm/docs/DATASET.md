## 2. Decision: FineWeb `sample-10BT`

* **Wikimedia** was dropped first — the HF copies are gated, and Wikimedia text
  is CC BY-SA 4.0, a *share-alike* licence whose obligations on a trained model
  are ambiguous.
* **Cosmopedia** has the cleanest licence (Apache 2.0) but the data is
  **synthetic**, produced by Mixtral. Training only on model-generated text is a
  poor test of a from-scratch LM and hides real-world text quirks.
* **FineWeb** is real English web text with **ODC-BY**, which asks only for
  attribution — no share-alike. It is the de-facto standard corpus for
  pretraining work.

## 3. Why the rows API and not a shard

Every FineWeb parquet shard is ~2 GB, which is an order of magnitude above the
~100-200 MB pilot the brief specifies:

```
2147292183  sample/10BT/000_00000.parquet
2146714409  sample/10BT/001_00000.parquet
 574962194  sample/10BT/014_00000.parquet
2147531358  data/CC-MAIN-2013-20/000_00000.parquet
```

So the corpus was pulled through the public **datasets-server rows API** from
the login node, which has outbound HTTPS, with an exact byte budget. Shards are
never downloaded. Compute nodes cannot do this at all (no DNS — `ENVIRONMENT_AUDIT.md`
§8/§9); they only ever *read the finished file from `/home`*.
