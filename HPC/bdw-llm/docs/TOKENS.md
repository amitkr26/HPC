## 1. Method

Every document from the pilot corpus (`docs/DATASET.md`) is encoded with the
Stage D tokenizer and separated by `<|eos|>`, forming **one contiguous token
stream**. That stream is then cut into fixed-length rows of `seq_len = 1024`,
which is what the training loop consumes.

* **dtype `int32`** — token ids 0..16383 all fit, and int32 moves to CUDA
  without a cast.
* **Shards of ~1M tokens** so the loader can memory-map and shuffle across
  shards rather than holding everything in RAM.

## 5. Scale check

38.2 M tokens from a 165 MB pilot is a useful regime for the next stages: a
small decoder-only Transformer can overfit it quickly, so architecture and
training-loop bugs surface in minutes rather than hours. The same code path
scales to a larger corpus later.
